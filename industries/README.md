# Industry packs

One JSON file per industry (`<id>.json`) drives that industry's MCP tools across the demo:

| Consumer | Reads | How |
|---|---|---|
| Cloud Run `industry-apis` | tools, personas | `services/industries/` copy + handlers in `services/packs/<id>.js` |
| Apigee proxy `<id>-mcp` and 3 products | tools, quotas, limit, personas | `apigee/scripts/gen_industry_mcp.py` |
| API hub entry for `<id>-mcp` | `label`, `basePath`, personas, tools, optional `apihub` | `apigee/scripts/apihub_catalog.py` (run by `provision_industry_pack.py`) |
| Live tests | tools, limit, story | `ui/tests/gateway-live.test.mjs` (section 5) |
| UI MCP tab | tools, areas, presets, persona flows | generated `ui/src/data/industryPacks.js` |
| Agent Showcase (UI) | `showcase.scenarios` | `showcaseScenariosFor` in `ui/src/utils/industryPacks.js` |
| Agent Showcase (ADK service) | `showcase.instruction`, `basePath` | `agents/app/industries/` copy, `profile_for` in `agents/app/profiles.py` |

[MAPPING.md](MAPPING.md) (generated by `node industries/mapping.mjs`) maps every industry to its AI-tab prompts, personas, MCP server, tools, showcase scenarios and customer themes.

Every pack's story has a $30 charge within policy and a $120 one over the limit. The backend only refuses a refund larger than what remains (`EXCEEDS_*`); the $50 rule is Apigee's. Tool names and preset ids are unique across packs (`node services/packs/check.js <id>` checks one pack, the services tests check all).

Industries the theme agent adds to the library have no pack and keep the generic `/mcp` tools and scenarios.

Every pack fills the same outcome slots, so the story works in every industry:

| Slot | Persona | Gateway outcome |
|---|---|---|
| `pii` | ops (Support & Sales) | 200; 401 for Analysts |
| `lookup`, `write` | ops | 200 |
| `money` | ops | 200 within `limit.max`; 403 `limit.code` over it (Apigee ExtractVariables + RaiseFault) |
| `metrics` | insights (Analysts) | 200 |
| `confidential` | insights | 200; 401 for Support & Sales |
| `forecast` | insights | quota <= 3/min, so the next call is 429 |

The Admin product has every tool, generous quotas and no business-rule limit (the ungoverned side of the Agent Showcase).

## Agent Showcase

When the theme's industry has a pack, both showcase agents get `showcase.instruction` and the pack's MCP server (`<id>-mcp`) in place of the generic `/mcp`; BigQuery and ServiceNow stay. The key still decides: the governed agent's Support & Sales key holds only the ops product, the ungoverned agent's admin key the Admin product. `showcase.scenarios` re-words the slots `lookup`, `multi-step`, `refund`, `over-reach`, `injection` and `burst`; "Ask again" repeats `lookup` and "Cheaper model?" stays neutral. `expect` may use `{label}`, `{opsCount}`, `{adminCount}` and `{limitMax}`.

Every pack's `showcase.instruction` ends with the same approval rule: when a refund, credit or waiver is refused because it needs approval, the agent says it was not applied, raises a ServiceNow incident with `createIncident` (category "Approval Request", priority "3 - Moderate") and gives the customer the incident number. The governed key can call only that ServiceNow tool (product **ServiceNow Tools MCP - Create Incident** on the Unified Sales App). Keep the rule when adding a pack.

Local preview: run `industry-apis` on 8091, the agent service with `INDUSTRY_APIS_LOCAL=http://localhost:8091`, and the UI with `AGENT_SHOWCASE_URL` pointing at it. `agents/app/gateway_sim.py` then makes the proxy's decisions (tool filter, 401, limit 403, 429).

## Add or change a pack

```bash
node services/packs/check.js <id>                         # one pack: slots, collisions, presets, story, showcase
node industries/sync.js                                   # validate + copy to services/, agents/ and the UI module
python3 apigee/scripts/gen_industry_mcp.py <id>           # apigee/proxies/<id>-mcp + 3 product JSON files
node industries/mapping.mjs                               # regenerate MAPPING.md (--refresh-themes with the UI running)
(cd services && npm test)                                 # handlers, MCP endpoint, pack checks
bash services/deploy_industry_apis.sh                     # Cloud Run industry-apis
python3 apigee/scripts/provision_industry_pack.py <id>    # proxy (dev + prod) + products + app access + API hub entry
(cd ui && npm run test:live)                              # includes the pack's live MCP tests
bash agents/deploy.sh                                     # agent service loads packs at start-up
```

Then deploy the UI (the MCP tab and showcase read the generated `ui/src/data/industryPacks.js`).

`validate.js` lists the rules. Changing `limit.max` means regenerating and redeploying the proxy, because Apigee conditions compare against literals.

### API hub

The last step of `provision_industry_pack.py` runs `apihub_catalog.py --only <id>-mcp` against API hub (`your-gcp-project`, `asia-southeast1`). It sets the proxy's Business Unit, Team, owner (`<team>@example.com`), style **MCP**, service type **Code**, maturity **Level 3**, target users Internal + Partner, and a description built from the pack. Versions are set to **Production**. If API hub fails, the step only prints a warning and the command to re-run; it never undoes the deploy.

> [!IMPORTANT]
> API hub only picks up a new Apigee proxy when the built-in Apigee X/Hybrid plugin runs its `sync-metadata` action. That runs every 6 hours, at 02:10, 08:10, 14:10 and 20:10 UTC (07:40, 13:40, 19:40 and 01:40 IST), and API hub rejects manual runs. On a first deploy the step therefore usually warns that `<id>-mcp` is not in the hub yet and prints the next sync time. Re-run `python3 apigee/scripts/apihub_catalog.py --only <id>-mcp` after that sync. `--wait <seconds>` polls for it instead.

Choose the pack's Business Unit and Team with an optional `apihub` block in `<id>.json`:

```json
"apihub": { "businessUnit": "financial-services", "team": "wealth-management", "teamName": "Wealth Management" }
```

- `businessUnit` must be one of the BU ids in `BUSINESS_UNITS` in [apihub_catalog.py](../apigee/scripts/apihub_catalog.py): `ai-platform`, `financial-services`, `health-public-services`, `energy-industrial`, `consumer-digital`, `enterprise-technology`, `platform-engineering`.
- `team` can be an existing team id (for example `retail-commerce`) or a new one. A new team is added to the hub's **Team** attribute automatically, with `teamName` as its display name.
- Without the block, the 15 original packs use `INDUSTRY_TEAMS`. A new pack gets its own team `<id>`, named after `label`, in `consumer-digital`, and the script prints a warning.

To re-catalogue a pack by hand, or to retry after the sync: `python3 apigee/scripts/apihub_catalog.py --only <id>-mcp` (add `--dry-run` to preview). A full `python3 apigee/scripts/apihub_catalog.py` run also catalogues every pack that has synced.
